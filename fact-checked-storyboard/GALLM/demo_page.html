From a patient question to a checked video

Ask a patient question. The answer is built live: facts come from a knowledge graph of clinical guidelines, one model writes a line for each fact, and a different model checks every line against its own fact. Lines that fail are rewritten once or removed. Then code picks what the video shows and makes it: two voices, a word-by-word speech check, and an animated doctor and patient.

Part 1 · Steps 1–3 · Code only

What the knowledge graph returned

The question's words are matched to the graph's own concept names, two fixed SPARQL queries collect claims and recommendations that mention them, and the best facts (at most 10) are kept with their guideline and page. The row below shows how many were found and why the rest were left out.

Show the SPARQL queries that were run for this question

Fixed queries written once in the code (graph_facts.py); only the concepts of the question are filled in. No model writes or changes them.

Part 2 · Steps 4–7

The script, line by line

Each fact becomes one slot. The writer (gpt-oss-20b) turns it into one plain spoken line. Every line then passes code checks and a judge (gpt-oss-120b) that sees only that line's own fact.

Part 3 · Step 8 · Code only
What the video shows, line by line

    
For each spoken line, code picks the camera, what the doctor and the patient do, and at most one object, only from fixed
      lists. An object must fit the words of its line, and an object the line warns against (a cigarette pack, a wine glass) is never shown.
      Nothing here writes or changes words: the patient's own question comes first, then the checked lines, with the spoken AI notice after
      the greeting. No model, no tokens.

    

    

  


  

    
Step 9 · Code and fixed tools
The video

    
Kokoro reads every line (the patient's question in a second voice, slower than normal speech). Whisper listens to each
      line and then to the finished sound track: one added, dropped or changed word stops the video. The approved doctor and patient are
      drawn frame by frame from the table above, and every caption must stay on screen long enough to read. No model and no tokens; it
      takes a few minutes. If any check fails, no video is made.
