Stage A: PDF Text Extraction – Running Example

Stage A reads PDF guideline files and produces raw text per page (and optional tables). Shown below are several real examples from the same guideline to illustrate how different page types are extracted.

Example document: Heidenreich, 2022, AHA,ACC,HFSA guidelines.pdf
a
Extract text
In: PDF files  |  Out: raw_text (pages)
→
raw_text (pages)
page, text, source, tables[]

What Stage A does: Loads PDFs from a directory (e.g. data/), uses PyMuPDF for main text and pdfplumber for table detection. For each page it: skips first N and last M pages (e.g. cover and references), extracts text blocks in reading order (with 2-column detection), dehyphenates line breaks, merges incomplete paragraphs, and filters noise (TOC lines, headers/footers, URLs, reference list lines). Tables are extracted separately into tables[]. Output matches ExtractText transform and stage_a_raw_text.json.

Two-column reading order

When a page has two columns (e.g. left and right text blocks), the code does not read row-by-row. It reads left column from top to bottom, then right column from top to bottom. PyMuPDF returns blocks with bounding boxes (x0, y0, x1, y1). The code finds the largest horizontal gap in block positions; if that gap is at least 22% of page width and each side has at least 3 blocks, the page is treated as 2-column. Blocks with x0 < boundary are sorted by (y0, x0) → left column order; blocks with x0 ≥ boundary are sorted the same way → right column order. Final order is left blocks first, then right blocks.

Left column (read first)
Block 1 (top)
Block 2
Block 3 (bottom)
→
Right column (read second)
Block 4 (top)
Block 5
Block 6 (bottom)

So the final page text order is: Block 1 → Block 2 → Block 3 → Block 4 → Block 5 → Block 6.

Processing steps with output examples

Each step: short input and the resulting output.

1. Skip pages
Pages at the start and end are skipped by configuration (default: skip first 3, last 5) to avoid covers, TOC, and references.
Input
PDF 89 pages; skip_first=3, skip_last=5. Pages 1–3 = cover/TOC, 85–89 = references.
→
Output
Only pages 4–84 in output. pages[0].page === 4, pages[1].page === 5, … pages[80].page === 84.
2. Two-column reading order
For two-column pages, blocks are ordered left column top→bottom, then right column top→bottom based on block bounding boxes.

Page with left blocks (A,B,C) and right blocks (D,E,F).

page.text order = A, B, C, D, E, F (left top→bottom, then right top→bottom).
3. Text blocks (cleaning)
Hyphenated line breaks and mid-word splits are joined to recover clean tokens before paragraph assembly.
Input
"heart fail\nure" "medica-\ntion"
→
Output
"heart failure" "medication"
4. Noise filtering
Table-of-contents lines, headers/footers, URLs, short all-caps metadata, and reference lines are removed; a REFERENCES heading can drop trailing pages.
Input (removed)
• TOC: "1.2. Organization of the Writing Committee ........ 5" • Short all-caps: "INTENDED USE" • Running header: "Heidenreich et al 2022 Guideline for the Management of Heart Failure" • Reference line: "1. Smith A, Jones B. Heart failure. N Engl J Med. 2020." • URL: "https://www.acc.org/guidelines"
Detection rules (collapsed):
TOC
Block contains 3+ consecutive dots (\.{3,}) and a page number at end (\b\d{1,4}\s*$); or starts with section numbering (^\d+(\.\d+)+) and ends with page number, and is short (≤220 chars, ≤18 words).
Headers / footers
Block is in the top 12% of the page (y0 ≤ 0.12×page height) or bottom 10% (y1 ≥ 0.90×page height), and matches: “Page N”, “N of M”, plain number, or short ALL CAPS (≤6 words).
Running header (start of page)
Regex: line containing “et al”, a year, and “Guideline(s)” near the start of the page text — stripped once from the beginning.
Reference lines
Line matches ^\d+\.\s+[A-Z][a-z]+\s+[A-Z] (e.g. “1. Smith A…”) or contains “et al.”; used in reference-zone pages and for REFERENCES section cutoff.
URLs / metadata
Block contains https?://, doi:, or “downloaded from” / “accessed on”; or (near start of doc) short line that is all caps + punctuation (≤60 chars) or ends with a 4-digit year (≤30 chars).
REFERENCES section
If a line equals “REFERENCES” (in first ~40 lines of a page) and the page has high reference-style density (e.g. numbered citations), that page and all following pages are dropped.
→
Output
These lines do not appear in page.text. Only body paragraphs kept. If "REFERENCES" heading found, that page and all after are dropped.
5. Tables
Tables are extracted separately via pdfplumber and stored as structured rows, not merged into the page text.
Input

"tables": [{ "title": "", "rows": [["Abbreviation","Meaning/Phrase"], ["ACEi","…"], ["ARNi","…"]] }]
6. Output per page (RawText / stage_a_raw_text.json)
Each page is serialized with page number, cleaned text, source filename, and any extracted tables.
Input
One extracted page (e.g. page 5, body text only).
→
Output
{ "page": 5, "text": "The term guideline-directed medical therapy (GDMT) encompasses clinical evaluation, diagnostic testing…", "source": "Heidenreich, 2022, AHA,ACC,HFSA guidelines.pdf", "tables": [] }

Summary (hidden)

  • Skip pages: First 3 and last 5 pages are skipped by default (cover, TOC, references). → Example above: pages 1–3 and 85–89 skipped; output starts at page 4.
  • Text blocks: PyMuPDF returns blocks with coordinates; blocks are ordered (2-column: left column top→bottom, then right column top→bottom; see “Two-column reading order” above), then cleaned (dehyphenation, mid-word newline merge, whitespace normalization). → Example above: "heart fail\nure" → "heart failure".
  • Noise filtering: TOC lines (leader dots + page number), short all-caps metadata lines, headers/footers, URL blocks, and reference-list lines are removed. A "REFERENCES" section can drop the rest of the document. → Example above: TOC, header, URL lines are removed.
  • Tables: pdfplumber detects and extracts tables per page; each table is stored as {"title": "", "rows": [[cell, ...], ...]} in the tables array — i.e. as structured rows/cells, not as consecutive sentences in the page text (see table renderings above). → Example above and in Example 3 (page 6).
  • Output: One object per page: page, text (full cleaned text), source (PDF filename), tables (array of table objects). Matches RawText / stage_a_raw_text.json. → Example above; full pages in Examples 1–4.
